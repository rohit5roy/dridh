# Recovery scenarios

> **Status date:** 2026-11-11. For each scenario, Dridh records the current state before recovering and never deletes or resets evidence blindly. **VERIFIED** means an automated test exercises the behaviour. **NOT BUILT** means there is no implementation to test.

Test paths are relative to `dridh/`. Scenarios marked as Docker tests need a Docker daemon; they run in CI's Python job.

| # | Scenario | Status | Behaviour and evidence |
|---|---|---|---|
| 1 | OpenCode process exits during an interactive conversation | VERIFIED | A session is only resumed when it is provably safe; otherwise a fresh session is started (`SESSION_UNSAFE`). Docker end-to-end scenario E2E-28 covers session resume and refusal of unknown sessions |
| 2 | Agent session exists but the Python process dies | VERIFIED | A per-run driver lock is held while a run is driven. If the process is killed the operating system drops the lock, `dridh execute resume` recovers the `RUNNING` run (audit event `execution.recover`), resets stories left `IN_PROGRESS` and continues from their worktrees. A live driver is never taken over. `tests/integration/test_executor_controller.py`: `test_killing_the_driving_process_releases_the_run`, `test_a_run_whose_driver_died_is_recovered_and_finishes`, `test_a_run_with_a_live_driver_is_not_taken_over` |
| 3 | Python tool subprocess exits unexpectedly | VERIFIED | Non-zero exit, timeout and cancellation are classified and reported; workers are terminated with their process group. Docker end-to-end scenario E2E-29 covers timeout and cancellation. `tests/unit/test_watchdog.py` |
| 4 | SQLite lock or contention | VERIFIED | A blocked writer waits up to `DRIDH_SQLITE_BUSY_TIMEOUT_MS` (default 10 s, bounded), then gets a retryable `DEPENDENCY_UNAVAILABLE` ("the workspace database is busy"), exit code 3, with nothing changed. A lock while opening is not reported as corruption. Readers are not blocked (WAL). `tests/integration/test_sqlite_contention.py` |
| 5 | Corrupt or incomplete Markdown output | VERIFIED | Ideator, Designer and Planner write documents atomically (temporary file, fsync, rename). A writer killed with SIGKILL after writing but before the rename leaves the previous document intact; the stray temporary file does not affect the next write. A canonical document truncated on disk afterwards is caught: a table row cut off mid-cell fails validation (`TABLE_ROW_UNTERMINATED`), and the hash check re-locks the next stage. `tests/integration/test_half_written_markdown.py` |
| 6 | Failed document correction attempt | VERIFIED | The repair loop is bounded at three and ends `BLOCKED` for a human. `tests/integration/test_planner_repair.py`, `tests/unit/test_stage_repair.py` |
| 7 | Jev timeout or invalid response | VERIFIED | Falls back to the deterministic path and records `FALLBACK_DETERMINISTIC`. `tests/unit/test_jev_checkpoints.py` |
| 8 | Embedding model missing or unavailable | VERIFIED | A labelled hashing embedder is used and reported as degraded. `tests/integration/test_code_reacher.py` |
| 9 | SQLite extension load failure | VERIFIED | Vector search falls back to an exact scan. `tests/integration/test_code_reacher.py` |
| 10 | Docker container fails to start | VERIFIED | Story tests run in a per-story container. A container that cannot be created or started (Docker exit 125), Compose services that do not become healthy, a network that cannot be created or an image that cannot be pulled are recorded as an infrastructure failure: the finding says the environment failed, not the code, and everything created so far is removed. With `execution.containers.mode: docker` and no Docker, Dridh refuses instead of running on the host. `tests/integration/test_story_containers.py`: `test_scenario_10_a_container_that_cannot_start_is_an_infrastructure_failure` (Docker test) |
| 11 | Compose network collision | VERIFIED | Each story gets its own Compose project, network and container, named from the workspace, run and story (with a hash) and labelled `io.dridh.workspace`, `io.dridh.run` and `io.dridh.story`; two stories never share one. Everything is removed after the tests whatever happened, and a crashed drive's leftovers are removed by label and project name when the run is driven again. `tests/integration/test_story_containers.py`: `test_scenario_11_parallel_stories_get_their_own_compose_project_network_and_service`, `test_stale_resources_of_a_crashed_run_are_removed_by_label_and_project_name` (Docker tests) |
| 12 | Worktree has uncommitted changes during cleanup | VERIFIED | Cleanup refuses a dirty worktree unless forced, and a forced removal first saves the whole working tree (tracked changes and untracked files) on `refs/dridh/recovery/...`. `dridh execute discard` also pins the story branch's tip before deleting it. `dridh recovery list` and `restore` bring the work back. `tests/unit/test_worktree_recovery.py`; `tests/integration/test_executor_controller.py`: `test_discarding_a_story_keeps_its_uncommitted_work_and_its_branch_tip` |
| 13 | PR head SHA changes after checks passed | VERIFIED | Eligibility is withdrawn. `tests/integration/test_delivery_engine.py`: `test_a_moved_pr_head_withdraws_eligibility` |
| 14 | Local integration conflict | VERIFIED | The PR and worktree are kept; nothing unlocks. `tests/integration/test_delivery_engine.py`: `test_a_merge_conflict_blocks_without_unlocking` |
| 15 | Code Reacher index fails after local integration | VERIFIED | An indexer exception after the push is recorded: the `INDEXED` gate is recorded as failed with the reason, dependents stay locked, the push stands, and a retry is idempotent. `tests/integration/test_delivery_engine.py`: `test_an_index_failure_after_integration_is_recorded_blocks_the_unlock_and_can_be_retried` |
| 16 | A human edits a reviewed document, making approval stale | VERIFIED | The review reopens; the plan approval is bound to a definition digest. `tests/integration/test_feature_lifecycle.py`: `test_changing_an_approved_document_reopens_the_review_and_recovers_when_restored` |

All sixteen scenarios are covered by automated tests.
